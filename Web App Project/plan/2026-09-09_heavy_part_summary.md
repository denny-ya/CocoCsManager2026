# 중수리 파트 전체 집계 및 센터별 펼침

## 변경 목적

기존 파트 검색은 대표 센터의 요약 행을 상단에 표시하지만 팝업은 파트 전체를 조회하여 건수가 달랐습니다. 중수리 상단, 파트 카드, 팝업, 엑셀 파트 실적을 모두 같은 파트 전체 범위로 통일합니다.

## 백업

- `backup/2026-09-09_093542_before_heavy_part_summary`에 수정 전 `src`, `plan`, `README.md`를 보관했습니다.
- 로컬 설계 파일의 백업입니다. 운영 구글 시트 데이터 자체를 복사한 것은 아닙니다.

## 집계와 화면

- 기존 원본 및 작업데이터의 날짜, 완료 판정, LT, 전월 이월 계산식을 유지합니다.
- `AS_MASTER_MAP`의 활성 중수리 파트를 바탕으로 집계 시 파트 행과 센터 행을 생성합니다. 매핑 시트 자체를 수정하지 않습니다.
- `AS_DAILY_SUMMARY`는 기존 30개 열을 유지하고 집계 행을 추가합니다.
- 파트 수량은 해당 파트의 모든 작업으로 직접 집계합니다. 센터별 평균 LT의 단순 평균을 사용하지 않습니다.
- 파트 검색의 상단 제목과 카드 제목은 서비스1~4입니다. 전체 검색에서는 팩토리와 네 파트가 기본 카드입니다.
- 서비스1·2와 팩토리에는 펼침을 표시하지 않습니다.
- 서비스3은 대구센터, 부산센터, 경남센터 순으로 펼칩니다.
- 서비스4는 호남센터, 충청센터, 제주센터 순으로 펼칩니다.
- 센터는 담당 마스터 매핑의 소속 센터 기준입니다. 실제 수리 장소를 변경하는 기능이 아닙니다.
- 등록된 센터는 0건이어도 표시합니다. 서비스3·4의 다른 센터명이나 센터 누락 작업은 지정 센터 뒤에 표시합니다. 센터명이 없으면 `센터 미지정`입니다.
- 중수리 미완료 팝업은 요약의 `미완료계`와 동일하게 접수대기도 포함합니다. 경수리의 기존 접수대기 구분은 유지합니다.
- 같은 파트의 상단, 카드, 팝업은 같은 날짜와 작업 범위를 사용합니다. 서비스3·4 하위 센터에 한해 센터 조건을 적용합니다.
- 웹앱 검색은 생성된 요약을 사용합니다. 작업의 파트/센터 분류는 요약 생성 시 한 번 준비하여 날짜별 반복 필터링을 줄였습니다.

## 엑셀

- 기존 열, 서식 및 레이아웃을 유지합니다.
- 중수리 전체 보고서는 기존과 같이 전체 합계, 팩토리, 서비스1~4를 출력합니다.
- 특정 파트의 중수리 보고서에는 해당 파트 전체 행만 출력합니다.
- 센터 행은 엑셀에 추가하지 않습니다. 파트와 센터 수량을 함께 합산하지 않습니다.

## 운영 반영 순서

이번 변경은 웹앱 표시 파일만 교체해서는 완료되지 않습니다. 데이터 집계 코드와 웹앱을 함께 반영해야 합니다. 전환 중 구버전 화면에 다른 센터 행이 보일 수 있으므로 이용이 적은 시간에 아래 작업을 연속으로 진행합니다.

1. 데이터시트에 연결된 Apps Script에 `plan/AS_DAILY_STATS_DATA_SHEET_Code.gs`의 새 내용을 반영합니다.
2. 데이터시트의 `AS 실적 관리 → 요약데이터 갱신`을 실행합니다. `refreshAsDailySummary()`를 인수 없이 실행해 기존 조회 기간 전체를 재생성하는 방법도 같습니다. 특정 날짜만 인수로 지정하면 기존 동작상 요약 시트가 해당 날짜 결과로 대체되므로 이번 전환에는 사용하지 않습니다.
3. 최신 원본의 작업데이터도 갱신해야 한다면 `실적 업데이트`를 사용하고 정상 종료를 확인합니다.
4. `AS_DAILY_SUMMARY`에서 중수리 `PART` 행과 서비스3·4의 `CENTER` 행 생성 및 기준일을 확인합니다.
5. 웹앱의 `src/Code.gs`, `src/JavaScript.html`을 반영하고 새 버전으로 배포합니다. 앞선 누적 표시 변경의 스타일도 운영에 반영되어 있어야 합니다.
6. 화면을 새로 열고 전체, 서비스3, 서비스4를 조회합니다. 상단 미완료와 팝업 수량, 펼친 센터 합계, 엑셀의 파트 수량을 확인합니다.

이전 센터 단위 요약만 남은 날짜에는 파트 집계 갱신 안내를 반환합니다. 이전 수치를 파트 전체 수치처럼 표시하지 않기 위한 검사입니다. 새 캐시 구분값을 사용하므로 이전 웹앱의 AS 조회 캐시를 재사용하지 않습니다. 세션 및 인증 로직과 권한 범위는 변경하지 않았습니다.

## 검증 결과

- 실제 요약 생성 함수를 메모리 시트로 실행하여 신규 행 생성, 반복 갱신, 과거 날짜 및 전체 기간 재생성을 검증했습니다.
- 전체, 서비스1~4, 팩토리의 6개 조건에서 접수, 완료, 미완료, 30일 이상 팝업과 요약값 일치를 확인했습니다.
- 서비스4 미완료 7건이 호남 2, 충청 3, 제주 2건으로 나뉘는 예시를 검증했습니다.
- LT 1, 3, 8, 8일인 완료 4건의 파트 평균이 5일인지 확인했습니다.
- 센터 누락 및 추가 센터, 미래 접수, 취소, 접수대기와 전월 접수 후 당월 완료 사례를 포함했습니다.
- 엑셀 출력 함수에서 전체 보고서 6개 행과 특정 파트 1개 행만 선택되는지 확인했습니다. 기존 서식 생성 함수는 변경하지 않았습니다.
- Chrome의 320, 360, 390, 430, 480, 900px에서 카드 배치, 초기 닫힘, 센터 순서 및 경수리 마스터 펼침을 확인했습니다.
- 실행 명령: `node tests/as-heavy-part.cjs`.
- 예시 화면과 브라우저 검증 파일: `outputs/heavy-part-review`.
- 운영 구글 시트 접근, 실제 모바일 기기 검증, 실제 Drive 엑셀 생성 및 운영 배포는 수행하지 않았습니다.

## 복구

문제가 발생하면 위 백업의 웹앱 소스와 데이터 집계 코드를 함께 복원한 뒤 기존 코드로 요약을 재생성합니다. 집계 행 구조도 함께 돌아가야 하므로 웹앱 파일만 복원하는 방식은 피합니다. 운영 배포를 변경했다면 이전 배포 버전도 함께 복구합니다.
