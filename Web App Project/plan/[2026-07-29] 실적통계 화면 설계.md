## 4. 기존 엑셀 구조 분석
### 4.1 `AS실적.xlsx`의 raw 구조
- `접수RAW`와 `RAW`는 모두 70개 컬럼으로 구성되어 있습니다.
- 두 시트의 헤더 구조는 동일합니다.
- `RAW`의 접수번호는 모두 `접수RAW` 안에 포함되어 있습니다.
- `접수번호` 중복은 확인되지 않았습니다.
- 두 raw의 주요 필드는 대부분 동일하며, 차이는 `센터완료` 보조 컬럼 일부에서만 확인되었습니다.

### 4.2 기존 수식 구조
- `일일실적` 시트는 `접수RAW`와 `RAW`를 `COUNTIFS`, `AVERAGEIFS` 등으로 집계합니다.
- `접수RAW`는 주로 접수/미완료 기준 집계에 사용됩니다.
- `RAW`는 주로 완료/취소/리드타임 기준 집계에 사용됩니다.
- 현재 엑셀에는 보조 컬럼이 포함되어 있습니다.
  - 접수일시
  - 접수확정일시
  - 접수월
  - 접수일
  - 접수누적
  - 약속일시
  - 완료일시
  - 완료일
  - 완료누적
  - 이관
  - 공장완료월
  - 공장완료
  - 리드타임
  - 리드타임(공장)
  - 리드타임(센터)
  - 장기미완료
  - 센터완료월
  - 센터완료

### 4.3 기존 수식의 주의점
- 일부 보조 수식에서 행 참조가 어긋난 것으로 보이는 부분이 있습니다.
- 예: `RAW` 시트의 `센터완료` 보조 컬럼에서 2행 기준 수식이 `C2`가 아닌 다른 행을 참조하는 사례가 확인되었습니다.
- 따라서 앱에서는 기존 보조 수식을 그대로 신뢰하기보다, 원본 컬럼 기준으로 가공 값을 새로 계산하는 방향이 안전합니다.

## 5. raw 통합 방향
### 5.1 결론
- raw는 하나의 통합 원본 테이블로 관리하는 것이 가능합니다.
- 통합 기준 키는 `접수번호`입니다.
- 최종적으로 `AS_RAW_UNIFIED` 테이블을 만들고, 원본 51개 컬럼을 그대로 보관하는 구조를 권장합니다.

### 5.2 권장 원칙

## 10. 실적 계산 기준 초안
### 10.1 공통 기준
- 기준일은 사용자가 앱 화면에서 선택합니다.
- 누적 기준은 기준일이 속한 월의 1일부터 기준일까지입니다.
- 파트 필터는 `전체`, `서비스1`, `서비스2`, `서비스3`, `서비스4`, `서비스팩토리`를 제공합니다.
- 수리구분 필터는 `경수리`, `중수리`를 제공합니다.
- `서비스팩토리`는 `중수리`만 선택 가능합니다.

### 10.2 경수리 기준 초안
- 접수 당일: `접수일자 = 기준일`
- 접수 누적: `접수일자`가 월초~기준일 범위
- 완료 당일: `완료일자 = 기준일`
- 완료 누적: `완료일자`가 월초~기준일 범위
- 미출동: 완료 건 중 `상태구분 = 전화상담(미출동)`
- 출동: 완료 건 중 미출동이 아닌 건
- 미완료 계: 접수되었으나 완료/취소가 아닌 건
- 접수대기: 미완료 건 중 `접수상태 = 접수대기`
- 미완료: 미완료 계 - 접수대기
- 장기미완료: 완료/취소가 아닌 건 중 `기준일 - 접수일자 >= 30`
- 접수취소 당일: `접수취소일자 = 기준일`
- 접수취소 누적: `접수취소일자`가 월초~기준일 범위
- 리드타임 평균: 완료 누적 건의 `(완료일시 - 접수일시)`를 숫자 일수로 계산한 뒤 평균
- `카트이동`, `카트폐기`, `AS완료` 상태는 경수리 완료로 포함합니다.
- `접수확정`, `방문약속` 상태는 경수리 미완료로 포함합니다.
- `접수취소`는 raw의 `완료구분` 값과 무관하게 취소로 우선 분류하며, 완료/미완료 집계에서 제외합니다.

### 10.3 중수리 기준 초안
- 센터 중수리: `상태구분`이 `센터입고수리` 또는 `센터수리완료`인 건
- 팩토리 중수리: `상태구분`이 `공장입고수리` 또는 `공장수리완료(인수)`인 건
- 센터 중수리 접수 기준: `접수일자`
- 팩토리 중수리 접수 기준: `이관일자`
- 센터 완료 기준: `센터수리일자`
- 공장 완료 기준: `공장수리완료일자`
- 센터 리드타임: `(센터수리일시 - 접수일시)`를 숫자 일수로 계산해서 사용
- 공장 리드타임: `(공장수리완료일시 - 이관일시)`를 숫자 일수로 계산해서 사용
- `공장입고수리` 상태라도 `공장수리완료일자(W열)` 또는 `공장수리완료시간(X열)`에 값이 있으면 완료로 분류합니다.
- `공장입고수리` 상태에서 W/X열이 모두 비어 있으면 미완료로 분류합니다.

### 10.4 중수리 센터/팩토리 분류 확정 기준
- `AS_RAW_UNIFIED`의 `H열 파트`에는 `서비스팩토리` 값이 직접 나오지 않습니다.
- 따라서 중수리의 센터/팩토리 구분은 `AS_RAW_UNIFIED!C:C`의 `상태구분`을 우선 기준으로 판정합니다.
- `상태구분`이 `센터입고수리` 또는 `센터수리완료`이면 `중수리` 중 `센터` 건으로 분류합니다.
- `상태구분`이 `공장입고수리` 또는 `공장수리완료(인수)`이면 `중수리` 중 `팩토리(본사)` 건으로 분류합니다.
- `공장입고수리`, `공장수리완료(인수)` 건은 앱 가공 단계에서 아래처럼 가상 파트/센터를 부여합니다.
  - `수리구분 = 중수리`
  - `파트그룹 = 서비스팩토리`
  - `센터명 = 팩토리(본사)`
  - `rowType = FACTORY`
  - `AS_DAILY_WORK.접수일 = AS_RAW_UNIFIED.이관일자`
- 팩토리 중수리에서 `이관일자`가 비어 있으면 `접수일`을 원본 접수일자로 대체하지 않고 비워두며, `검증메모`에 `팩토리 이관일 누락`을 남깁니다.
- `센터입고수리`, `센터수리완료` 건은 앱 가공 단계에서 아래처럼 분류합니다.
  - `수리구분 = 중수리`
  - `파트그룹 = AS_RAW_UNIFIED!H:H 원본 파트`
  - `센터명 = AS_MASTER_MAP`의 담당마스터코드/담당마스터 매핑 기준 센터
  - `rowType = CENTER`

| AS_RAW_UNIFIED C열 상태구분 | 수리구분 | 파트그룹 | 센터명 | rowType |
| --- | --- | --- | --- | --- |
| 센터입고수리 | 중수리 | 원본 파트 | 담당자 매핑 센터 | CENTER |
| 센터수리완료 | 중수리 | 원본 파트 | 담당자 매핑 센터 | CENTER |
| 공장입고수리 | 중수리 | 서비스팩토리 | 팩토리(본사) | FACTORY |
| 공장수리완료(인수) | 중수리 | 서비스팩토리 | 팩토리(본사) | FACTORY |

#### 수식 설계 시 주의사항
- 중수리에서 `서비스팩토리`는 raw 원본 파트가 아니라 `상태구분`으로 만들어내는 가상 파트입니다.
- `AS_DAILY_WORK`의 `파트그룹`, `센터명`, `rowType`, `서비스팩토리대상여부` 수식은 반드시 `상태구분`의 공장수리 값을 먼저 판정해야 합니다.
- `AS_DAILY_SUMMARY`에서 파트필터가 `서비스팩토리`일 때는 `파트그룹 = 서비스팩토리`인 중수리 FACTORY 행만 집계합니다.

### 10.5 처리상태 판정 우선순위
raw의 `완료구분`이 실제 업무 상태와 다르게 들어오는 사례가 있으므로, 앱 계산용 `처리상태`는 아래 우선순위로 판정합니다.

1. 취소
2. 중수리 공장 완료
3. 중수리 센터 완료
4. 경수리 완료
5. 중수리 미완료
6. 경수리 미완료

#### 취소 우선 판정
- `접수상태 = 접수취소`이면 취소로 분류합니다.
- `상태구분 = 접수취소`이면 취소로 분류합니다.
- `접수취소일자(AI열)`에 값이 있으면 취소로 분류합니다.
- 취소 건은 완료/미완료 집계에서 제외하고, 접수취소 당일/누적 집계에만 포함합니다.
- `접수상태 = 미처리`는 단독 분류 기준으로 사용하지 않습니다.
- 현재 확인된 `미처리` 건은 `센터입고수리` 또는 `공장입고수리` 상태이므로, 반드시 `상태구분` 기준으로 중수리 미완료 여부를 판정합니다.

#### 경수리 완료/미완료 판정
- `상태구분`이 `카트이동`, `카트폐기`, `AS완료`이면 경수리 완료로 포함합니다.
- `상태구분`이 `부품교체`, `점검수리`, `전화상담(미출동)`이고 `완료일자(Y열)`에 값이 있으면 경수리 완료로 포함합니다.
- `상태구분`이 `접수확정`, `방문약속`이면 경수리 미완료로 포함합니다.
- 위 조건에 해당하지 않더라도 `완료구분 = 미완료`이고 취소가 아니면 경수리 미완료 후보로 분류하되, `검증메모`에 확인 대상임을 남깁니다.

#### 중수리 완료/미완료 판정
- `상태구분 = 센터수리완료`이면 중수리 센터 완료로 분류합니다.
- `상태구분 = 센터입고수리`이면 중수리 센터 미완료로 분류합니다.
- `상태구분 = 공장수리완료(인수)`이면 중수리 팩토리 완료로 분류합니다.
- `상태구분 = 공장입고수리`이고 `공장수리완료일자(W열)` 또는 `공장수리완료시간(X열)`에 값이 있으면 중수리 팩토리 완료로 분류합니다.
- `상태구분 = 공장입고수리`이고 W/X열이 모두 비어 있으면 중수리 팩토리 미완료로 분류합니다.

### 10.6 리드타임 숫자 변환 기준
- raw의 시스템 리드타임 컬럼은 문자화되어 있어 앱 집계 기준으로 사용하지 않습니다.
- `AS_DAILY_WORK`에서는 원본의 실제 날짜/시간 컬럼을 조합해 리드타임을 화면/집계용 숫자 일수로 계산합니다.
- 변환된 숫자 컬럼을 기준으로 `AS_DAILY_SUMMARY`의 `리드타임평균`을 계산합니다.
- 변환 실패 또는 빈 값은 평균 계산에서 제외하고, 필요 시 `검증메모`에 남깁니다.
- 기존 `AS실적.xlsx` 보조 수식 확인 결과, 리드타임 계산 기준은 아래와 같습니다.
  - 고객 리드타임: `(완료일자 + 완료시간) - (접수일자 + 접수시간)`
  - 센터 리드타임: `(센터수리일자 + 센터수리시간) - (접수일자 + 접수시간)`
- 공장 리드타임은 운영 기준상 `(공장수리완료일자 + 공장수리완료시간) - (이관일자 + 이관시간)`으로 계산합니다.
- 경수리 고객 리드타임은 raw의 `리드타임(고객)` 값을 쓰지 않고, `접수일시 → 완료일시` 기준으로 재계산하는 것을 우선합니다.
- 중수리 센터 리드타임은 raw의 `리드타임(센터)` 값을 쓰지 않고, `접수일시 → 센터수리일시` 기준으로 재계산하는 것을 우선합니다.
- 공장 리드타임은 raw의 `리드타임(이관)`을 그대로 쓰지 않고, `이관일시 → 공장수리완료일시` 기준으로 재계산하는 것을 우선합니다.
- 단, 시작/종료 일시가 비어 있어 재계산할 수 없는 경우에는 `검증메모`에 남기고 평균 계산에서 제외합니다.
- 리드타임 컬럼 자체로 수리구분을 판정하지 않습니다. 먼저 `상태구분`으로 경수리/중수리를 판정한 뒤, 해당 리드타임 값을 집계에 사용합니다.

### 10.7 장기미완료 기준
- 장기미완료는 `완료/취소가 아닌 건` 중 `기준일 - 접수일자 >= 30`인 건으로 정의합니다.
- 기준일에 따라 결과가 달라지므로 `AS_DAILY_SUMMARY` 생성 시점에 기준일 기준으로 계산합니다.
- 기존 문서의 `미완료4일이상` 표현은 앞으로 `장기미완료` 또는 `미완료30일이상`으로 대체합니다.

### 10.8 담당자/마스터 매핑 운영 기준
- 이번 달부터 `김성휘` 담당 건은 `김민규`로 완전히 대체되는 것으로 봅니다.
- 따라서 `AS_MASTER_MAP`의 경수리 대구센터 담당자 기준은 `김성휘`가 아니라 `김민규`를 사용합니다.
- raw에 과거 `김성휘` 건이 남아 있으면 앱 가공 단계에서 `김민규` 실적으로 대체 집계합니다.
- `담당마스터 = 김성휘` 또는 김성휘 담당 코드로 확인되는 건은 `담당마스터 = 김민규`로 정규화한 뒤 `AS_MASTER_MAP`과 매칭합니다.
- `담당마스터코드` 또는 `담당마스터`가 누락된 raw 건은 센터/담당자 매핑을 정확히 할 수 없습니다.
- 담당자 또는 파트가 비어 있는 raw 건은 억지로 다른 담당자/파트에 배정하지 않고 누락 데이터로 둡니다.
- 누락 데이터는 전체 집계에는 포함할 수 있으나, 파트/센터/담당자 세부 집계에는 배정하지 않습니다.
- 이 경우 전체 합계와 세부 합계가 1건 이상 차이날 수 있으므로 `검증메모`에 `파트/담당자 누락`으로 남깁니다.
- 향후에도 시스템 raw에서 담당자 누락 건이 발생하면 운영상 누락으로 보고, 가능한 경우 원본에서 담당자 입력 후 다시 집계합니다.

### 10.9 헤더 검증 및 기준일 필터 기준
- `AS_RAW_UNIFIED`는 매일 raw 헤더를 포함해 붙여넣으므로, 앱 계산 전 원본 헤더 검증을 수행합니다.
- 최소 검증 대상은 `완료구분`, `접수상태`, `상태구분`, `접수번호`, `파트`, `담당마스터코드`, `담당마스터`, `접수일자`, `접수시간`, `완료일자`, `완료시간`, `센터수리일자`, `센터수리시간`, `공장수리완료일자`, `공장수리완료시간`, `이관일자`, `이관시간`, `접수취소일자`입니다.
- 필수 헤더가 없거나 순서가 바뀐 것으로 확인되면 집계를 중단하고 오류 메시지를 반환합니다.
- 모든 당월 누적 집계는 `기준월 1일 <= 대상일 <= 기준일` 조건을 사용합니다.
- 기준일 이후의 접수/완료/취소/센터완료/공장완료 건은 당일/누적 집계에서 제외합니다.

## 11. UI 설계 방향
### 11.1 최종적으로 선호한 방향
- 현대적인 모바일 앱 스타일
- 상단 그라데이션 헤더
- 필터는 pill 형태 또는 카드형 컨트롤
- 주요 KPI는 크게 표시
- 상세는 엑셀형 표보다 모바일 친화적인 리스트-테이블 하이브리드

### 11.2 화면 구성
- 상단 헤더
  - 뒤로가기
  - `AS 일일실적`
  - 기준일 표시
- 필터 영역
  - 날짜 선택
  - 파트 드롭다운
    - 전체
    - 서비스1
    - 서비스2
    - 서비스3
    - 서비스4
    - 서비스팩토리
  - 수리구분 드롭다운
    - 경수리
    - 중수리
  - 검색 버튼
  - 안내 문구: `서비스팩토리는 중수리만 선택 가능`
- KPI 영역
  - 접수
  - 완료
  - 미완료
  - 취소
  - LT
- 상세 영역
  - 상단에만 `구분 / 접수 / 완료 / 미완 / LT / 취소` 표시
  - 각 행은 숫자만 크게 표시
  - 전체/서비스/센터/담당자 행은 색상과 굵기로 구분

### 11.3 성능 관련 방향
- 색상 다양성 자체는 성능에 큰 영향을 주지 않습니다.
- 성능에 영향을 주는 주요 요소는 데이터 조회 횟수, Apps Script 집계 시간, DOM 렌더링 행 수입니다.
- 따라서 UI는 `AS_DAILY_SUMMARY`만 읽고, raw 전체를 매번 화면에서 계산하지 않는 방향이 좋습니다.
- 상세 행은 처음에는 요약 행 중심으로 표시하고, 필요시 센터/담당자 단위 확장도 고려합니다.

## 12. Apps Script 구현 방향 초안
### 12.1 서버 함수

## 15. 확정 운영 기준
### 15.1 raw 데이터 붙여넣기 방식
- `AS_RAW_UNIFIED` 시트에는 매일 시스템에서 받은 무가공 raw 데이터를 그대로 복사/붙여넣기 합니다.
- 복사/붙여넣기 시 raw 헤더를 포함합니다.
- `AS_RAW_UNIFIED`의 1행은 항상 원본 헤더입니다.
- `AS_RAW_UNIFIED`의 2행부터 실제 데이터입니다.
- 원본 컬럼 범위는 `A:AY` 51개 컬럼입니다.
- 컬럼 순서는 시스템 raw 원본 순서를 그대로 유지합니다.
- `AS_RAW_UNIFIED`에는 수식이나 앱 계산용 보조 컬럼을 추가하지 않습니다.
- 앱 계산용 수식은 `AS_DAILY_WORK`에서 `AS_RAW_UNIFIED!A2:AY`를 참조해 작성합니다.

### 15.2 확정된 참조 기준
```text
AS_RAW_UNIFIED!A1:AY1 = 원본 헤더
AS_RAW_UNIFIED!A2:AY  = 원본 데이터
```

### 15.3 수식 작성 기준
- `AS_DAILY_WORK`는 `AS_RAW_UNIFIED`의 2행부터 데이터를 참조합니다.
- `접수번호`가 비어 있으면 빈 행으로 처리합니다.
- 기본 수식 패턴은 아래 형태를 사용합니다.

```gs
=ARRAYFORMULA(IF(AS_RAW_UNIFIED!D2:D="",,AS_RAW_UNIFIED!D2:D))
```

### 15.4 운영상 주의사항
- 매일 raw를 붙여넣을 때 기존 데이터는 삭제 후 새 데이터로 교체합니다.
- 헤더가 포함되어야 하므로 데이터는 항상 `A1`부터 붙여넣습니다.
- 시스템 raw의 컬럼 순서가 바뀌면 `AS_DAILY_WORK` 수식과 앱 집계가 깨질 수 있으므로, 헤더 검증 로직을 추후 Apps Script에 추가하는 것을 권장합니다.
- 원본 보존과 계산 안정성을 위해 `AS_RAW_UNIFIED`에는 절대 수식 컬럼을 섞지 않습니다.
